# CODEFORGE — сайт студии цифровой разработки

Премиальный тёмный сайт IT-компании с живой анимированной сценой программиста на первом экране, многошаговой формой заказа, реальным сохранением заявок в базу данных, уведомлениями в Telegram/e-mail и защищённой админ-панелью.

![Hero](public/assets/img/og-image.png)

## Что внутри

| Часть | Реализация |
|---|---|
| Фронтенд | HTML + CSS + JavaScript без сборки; страницы рендерятся на сервере из редактируемого контента |
| Hero-сцена | Анимированная сцена 1600×900 (SVG + DOM): программист печатает — каждый символ в редакторе вызывает нажатие пальца нужной руки, голова поворачивается к активному монитору, терминал выполняет команды, превью «перезагружается» после каждого файла. Код сменяется: TypeScript, CSS, Python, HTML, Go |
| Бэкенд | Node.js + Express (`server/`) |
| База данных | SQLite из коробки (встроенный `node:sqlite`, ноль настроек) или PostgreSQL / Supabase через `DATABASE_URL` |
| Валидация | Zod на сервере + зеркальная валидация на клиенте |
| Загрузка файлов | Multer: белый список расширений, проверка сигнатур файлов, лимиты, случайные имена, хранение вне публичной папки |
| Антиспам | Honeypot-поле, подписанный токен формы (минимальное время заполнения, одноразовость), лимит заявок с IP, проверка MX-записей домена почты |
| Уведомления | Telegram Bot API, e-mail команде и подтверждение клиенту (SMTP / Nodemailer) |
| Админ-панель | `/admin` — заявки, редактирование всего контента сайта, портфолио, медиафайлы, пароль, версии |
| SEO | meta, Open Graph, JSON-LD, ЧПУ `/projects/<slug>`, `/sitemap.xml`, `/robots.txt`, серверный рендеринг страниц проектов и правовых страниц |

## Быстрый старт

Требуется **Node.js 22.13+**.

```bash
npm install
cp .env.example .env
npm run hash-password          # введите пароль → вставьте ADMIN_PASSWORD_HASH в .env
npm start                      # http://localhost:3000
```

- Сайт: `http://localhost:3000`
- Админ-панель: `http://localhost:3000/admin` (логин `ADMIN_USER`, по умолчанию `admin`)
- Тесты API: `npm test`

Для разработки без хеша можно временно задать `ADMIN_PASSWORD=...` в `.env`.

## Настройка (.env)

Все переменные описаны в [`.env.example`](.env.example). Главное:

- `SITE_URL` — публичный адрес (canonical, Open Graph, sitemap, ссылки в уведомлениях).
- `SESSION_SECRET` — случайная строка ≥ 32 символов, **обязательна в production**.
- `DATABASE_URL` — пусто = SQLite в `data/`; строка подключения Postgres/Supabase = PostgreSQL. Таблицы создаются автоматически.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — уведомления о новых заявках.
- `SMTP_*`, `MAIL_FROM`, `MAIL_NOTIFY_TO` — письма команде и подтверждение клиенту.
- `TRUST_PROXY=true` — если сайт за nginx / Render / Railway (корректные IP для лимитов).

### Supabase

Settings → Database → Connection string (URI) → вставьте в `DATABASE_URL`. SSL включается автоматически для доменов Supabase.

## Деплой на Vercel

Проект готов к Vercel: `vercel.json` раздаёт статику из `public/`, а все страницы и API обслуживает serverless-функция `api/index.js`. На Vercel нет постоянного диска, поэтому заявки хранятся в **Supabase (PostgreSQL)**, а файлы — в **Supabase Storage**.

**Самый простой способ — интеграция Vercel ↔ Supabase** (ключи копировать не нужно):

1. Vercel → ваш проект → **Storage** → **Connect Database** (или **Integrations → Supabase**) → выберите существующий проект Supabase или создайте новый → **Connect**. Интеграция сама добавит `POSTGRES_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_JWT_SECRET` — сайт их понимает.
2. **Settings → Environment Variables** → добавьте одну переменную `ADMIN_PASSWORD` (пароль входа в админку, потом смените его в «Настройках»). По желанию: `SITE_URL`, `TELEGRAM_BOT_TOKEN`, `SMTP_*`.
3. **Deployments → ⋯ → Redeploy**.
4. Откройте `https://ваш-сайт/admin` (логин `admin`).

Вручную (без интеграции) задайте `DATABASE_URL` (Supabase → Connect → Transaction pooler), `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SESSION_SECRET` (≥ 32 символов) и `ADMIN_PASSWORD_HASH` / `ADMIN_PASSWORD`.

Проверить подключение: `https://ваш-сайт/api/health` — должно быть `"db":"postgres"`, `"storage":"supabase"`, `"sessionSecret":true`.

Ограничение Vercel: тело запроса до 4,5 МБ, поэтому на Vercel файлы к заявке — до 4 МБ суммарно, изображения в медиатеку — до 4 МБ. Видео для первого экрана загружайте на внешний хостинг и вставляйте ссылкой.

Пока база не подключена, сайт работает и показывает исходные тексты, а форма заявок и админка сообщают, что нужно задать `DATABASE_URL`.

### Если деплой на Vercel падает

- **`Resource provisioning failed` (деплой падает за секунду, логов сборки нет)** — это не ошибка зависимостей.
  Vercel не может подготовить подключённый ресурс Supabase: проект Supabase **на паузе** (бесплатные проекты
  засыпают после недели простоя) или не может создать ветку БД для деплоя.
  1. Supabase Dashboard → проект → **Restore / Unpause project**.
  2. Vercel → проект → **Storage** → Supabase → **Settings**: отключите создание ветки БД на деплой
     (deployment action «branch»), если не нужна отдельная БД для превью.
  3. Vercel → **Deployments** → Redeploy.
- **`База данных не подключена` / 503 при входе в админку** — не задан или неверен `DATABASE_URL`.
  Удалите собственный `DATABASE_URL`, если подключена интеграция Supabase: сайт сам возьмёт `POSTGRES_URL`.
  Неверные значения (например, с `[YOUR-PASSWORD]`) пропускаются, и сайт пробует следующую переменную.
- **`SUPABASE_URL` указывает не на тот проект**, что ключ `SUPABASE_SERVICE_ROLE_KEY`: адрес берётся из ключа
  автоматически, в логах будет предупреждение.

## Деплой на свой сервер

```bash
NODE_ENV=production npm start
```

Нужен постоянный диск для `data/` (SQLite и файлы) либо `DATABASE_URL` + Supabase Storage.

## Админ-панель

`/admin` — вход по логину и паролю или через Google-аккаунт.

- **Заявки** — статистика и график посещений за 14 дней, поиск, фильтры, детали, смена статуса, заметки, история, файлы клиентов, удаление (спам), экспорт CSV.
- **Контент сайта** — все тексты и блоки главной страницы: первый экран (и фоновое видео), услуги, «О нас» и счётчики, этапы работы, форма заказа (можно временно закрыть приём заявок), преимущества, FAQ, призыв к действию, контакты, соцсети, подвал, SEO и Open Graph, получатели уведомлений. Каждый раздел можно скрыть с сайта, элементы списков — добавлять, удалять и переставлять.
- **Портфолио** — добавление, редактирование, скрытие, удаление и сортировка проектов, обложки, страницы проектов `/projects/<адрес>`, пометка «Демо-концепт».
- **Дизайн и анимации** — фон, который стоит на месте при прокрутке (северное сияние, частицы, сетка, своя картинка или видео), цвета подсветки, затемнение, переключатели анимаций: фиксированный главный экран, появление заголовков по словам, 3D-наклон карточек, заставка, полоса прогресса, курсор, кнопка «Наверх».
- **Дополнительные разделы** — порядок блоков на главной, объявление вверху, бегущая строка, цены (тарифы), отзывы, плавающая кнопка «Связаться», cookie-уведомление, Яндекс Метрика / Google Analytics, режим обслуживания (посетители видят заглушку, админ — сайт).
- **Фото и видео** — загрузка из галереи телефона или с компьютера, фото до 15 МБ, видео (MP4, MOV, WEBM) до 50 МБ. На Vercel большие файлы идут напрямую в Supabase Storage, минуя лимит 4,5 МБ. Любое поле с картинкой или видео загружает файл одной кнопкой.
- **Интеграции**
  - *Telegram-бот*: вставьте токен от @BotFather, и вебхук настроится сам. Свой чат можно подключить по ссылке, по номеру телефона (бот попросит поделиться контактом) или по Telegram ID (команда `/id`). Под каждой заявкой есть кнопки смены статуса, у бота команды `/orders`, `/stats`, `/stop`.
  - *Вход через Google*: Client ID и Secret из Google Cloud плюс список разрешённых адресов. Через этот вход можно восстановить доступ: после входа через Google новый пароль задаётся без старого.
- **Конструктор сайтов** (`/create`). Клиент выбирает шаблон (лендинг для бизнеса, визитка специалиста, портфолио, кафе или ресторан), заполняет анкету в пять шагов, загружает фото из галереи и сразу получает сайт по адресу `/s/<адрес>`. Новый сайт — черновик с плашкой «Предпросмотр» до оплаты; можно включить публикацию сразу. Клиент правит свой сайт в личном кабинете по секретной ссылке, она приходит на почту, если настроен SMTP. О новом сайте приходит уведомление в Telegram.
- **Сайты клиентов** — список с владельцами, публикация с отметкой об оплате, возврат в черновик, отключение, новая ссылка для клиента (старая перестаёт работать), удаление.
- **Настройки** — смена пароля (завершает остальные сеансы), резервная копия контента в файл и восстановление из файла, история версий, сброс к исходному, состояние сервера.

Изменения появляются на сайте в течение ~10 секунд после сохранения.

## Видео вместо анимированной сцены (опционально)

Сцена программиста нарисована кодом и работает без внешних файлов. Если у вас есть лицензированное видео, укажите ссылки в админке: **Контент сайта → Главный экран → Фоновое видео**. Видео запускается автоматически, без звука и элементов управления, зацикливается и плавно заменяет сцену после загрузки; на телефонах берётся облегчённая версия.

```
api/index.js          точка входа для Vercel
vercel.json           конфигурация Vercel
public/               статика (CSS, JS, изображения, админка)
  assets/css/main.css дизайн-система и все секции
  assets/js/main.js   навигация, анимации появления, счётчики, курсор, частицы, FAQ
  assets/js/hero-scene.js   живая сцена программиста
  assets/js/order-form.js   многошаговая форма заказа
  admin/              админ-панель
server/
  index.js            Express-приложение и API
  db/                 адаптеры SQLite и PostgreSQL
  validation.js       Zod-схемы, проверка домена почты
  security.js         токены формы, лимиты, сессии, хеш паролей
  uploads.js          безопасная загрузка файлов
  notify.js           Telegram и e-mail
  content.js          модель редактируемого контента и исходные тексты
  storage.js          хранилище файлов: локальный диск или Supabase Storage
  views/              шаблоны главной страницы, шапки и подвала
  render.js, content/ страницы проектов и правовые страницы
test/api.test.js      интеграционные тесты API
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/form-token` | антиспам-токен формы |
| POST | `/api/orders` | создание заявки (multipart) → `{ number }` |
| POST | `/api/admin/login`, `/api/admin/logout` | вход/выход |
| GET | `/api/admin/orders?q=&status=&service=&budget=&sort=&page=` | список с поиском и фильтрами |
| GET/PATCH | `/api/admin/orders/:id` | детали / смена статуса и заметки |
| GET | `/api/admin/orders/:id/files/:fileId` | скачивание файла |
| GET | `/api/admin/stats`, `/api/admin/export.csv` | статистика, экспорт |

## Перед запуском в продакшн заменить

- контакты `hello@codeforge.dev`, `@codeforge_studio` и ссылки на соцсети — сейчас это заглушки, меняются в админке (**Контент сайта → Контакты и подвал**);
- тексты политики конфиденциальности и соглашения (`server/content/`) — проверить с юристом и добавить реквизиты;
- проекты в портфолио — демонстрационные концепты и везде помечены как «Демо-концепт».
